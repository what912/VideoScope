# ADR 0001：默认本地分析且不上传视频

- 状态：已接受
- 日期：2026-07-28
- 决策范围：VideoScope v0.1 核心产品与默认配置

## 背景

VideoScope 分析的输入可能是尚未发布的生成视频、企业内部评测素材、
包含个人信息的画面，以及与创作意图相关的提示词。证据帧和报告也
可能暴露与源视频相同的敏感内容。

v0.1 所需的元数据、镜头、黑屏、冻结、相对模糊和全局亮度闪烁分析
都可以由本地 FFmpeg/ffprobe 和 CPU 数值算法完成。把核心流程依赖于
远程服务不会为这些基础能力提供必要条件，反而会增加数据传输、
网络不可用、服务变化、成本和结果不可复现等风险。

## 决策

VideoScope 核心流程采用 local-first：

- 默认只读取用户明确指定的本地视频；
- 默认在本机 CPU 上完成探测、解码、分析和报告生成；
- 默认不上传视频、音频、提示词、证据帧、特征、日志或报告；
- 默认不发送遥测或调用远程 API；
- 默认不下载模型、权重或测试素材；
- JSON、HTML 和证据写入用户选择的本地输出目录；
- 基础安装和基础测试必须能在断网环境运行。

源视频以只读方式处理。报告不记录个人绝对路径，原始提示词默认不
写入报告。

## 理由

### 隐私最小化

不传输是减少视频和提示词泄露风险最直接、最可验证的默认方式，也
避免让用户必须理解某个远程服务的保留与训练政策才能运行基础诊断。

### 可复现性

本地工具、算法、版本和配置可以记录并固定。远程模型或服务可能在
不通知客户端的情况下变化，使同一视频难以产生确定性结果。

### 离线可用性

研究环境、企业网络和素材审查流程可能没有稳定互联网连接。基础
诊断不应因为断网、配额、账号或服务中断而不可用。

### 可移植与可审计

用户可以检查本地进程、依赖、配置和输出。CPU 基础版不要求 GPU、
云账号或大型模型，降低了部署和审计成本。

## 后果

正面后果：

- 默认数据流简单，隐私边界清楚；
- 基础功能可离线运行和测试；
- 结果更容易固定版本并复现；
- 不产生远程调用成本或供应商依赖。

代价和限制：

- CPU 分析可能比 GPU 或云端方案慢；
- v0.1 不提供需要大模型的语义判断；
- 用户负责本地输出目录和证据帧的访问控制；
- 跨平台 FFmpeg 构建差异仍需测试和记录。

## 可选远程能力

未来可以提供本地或远程 AI 插件，但必须同时满足：

- 用户显式安装、配置并启用；
- 执行前明确说明会传输什么数据、传往哪里、用于什么目的；
- 未启用时不导入 provider、不联网、不下载模型；
- 报告记录 provider、模型和配置版本；
- 提供离线 fake provider 用于测试；
- 插件失败不破坏 CPU 基础报告；
- 远程插件不能成为 v0.1 报告读取或基础检测的必要条件。

启用可选远程插件是用户的主动选择，不改变默认不上传的决策。

## 步骤 15 补充：共享模型运行时和派生特征

可选 AI 基础设施继续遵守本 ADR：

- 基础安装、CPU 分析和基础测试不安装或导入真实 AI 运行库；
- provider 注册是惰性的；列出或检查模型不会加载权重、探测 GPU 或
  建立网络连接；
- 默认可以读取已经存在的本地模型缓存，但本地权重缺失时不会隐式
  下载；
- 交互式下载需要明确确认，非交互式下载必须显式传入
  `--allow-model-download`；
- 一个共享 Manager 负责所有 detector 的模型实例，避免重复加载；
- provider 异常由 detector runner 转换为 `detector_error`，CPU
  Findings 继续保留。

帧 embedding 虽不是原图，仍可能保留可关联输入内容的语义信息，因此
按敏感派生数据处理：

- 只写入平台本地缓存目录或用户明确指定的目录；
- 缓存键不包含文件名、个人路径或提示词；
- 默认不上传 embedding，不写入 HTML 证据，也不发送遥测；
- 缓存按视频哈希、帧时间、模型与预处理版本隔离，避免跨模型误用；
- 用户负责缓存目录权限、备份和生命周期；未来清理命令必须显式确认
  精确目标，不能静默删除其他应用数据。

## 未选择的方案

### 默认上传到托管分析服务

拒绝。它扩大隐私和合规风险，破坏离线使用，并引入账号、配额和
服务稳定性依赖。

### 首次运行自动下载大型模型

拒绝。它使基础安装依赖网络和大量存储，也会模糊权重许可证及数据
流向。模型必须是未来显式选择的可选能力。

### 只提供远程 VLM 结论

拒绝。v0.1 的可观察视频异常可以由 CPU 基础算法完成；远程 VLM
无法替代确定性时间区间、证据和检测器故障状态。

## 步骤 16 补充：本地 Prompt alignment

`prompt_alignment` 使用显式安装和启用的本地 OpenCLIP provider。
视频、抽样帧、prompt 和 embedding 不发送到外部 API。模型权重是唯一
可能触发网络访问的资产，并且必须在共享 Manager 的下载权限检查之后
才允许下载：交互终端明确确认，非交互调用显式传入
`--allow-model-download`。

报告可以在用户明确提供 prompt 时保留原文，并记录 scene 级相似度和
证据。这些本地产物及 embedding 缓存可能包含敏感语义，仍由用户控制
目录权限和生命周期。CLIP 相似度不等于完整语义验证，也不用于形成
未经校准的总质量分。

## 步骤 17 补充：本地视觉一致性特征

`visual_semantic_drift` 只在用户显式启用 AI profile 后运行。OpenCLIP
或 DINOv2 只读取本地抽样帧，embedding 与诊断曲线保留在本地缓存和
报告中，不发送到外部 API。DINOv2 的 torch hub 代码与权重均受统一
下载权限控制；已有完整缓存可以离线使用，缺少任一资源时不得静默联网。

视觉 embedding 仍属于可能关联源视频的敏感派生数据。检测器只描述
同一镜头内相对于场景基线的特征突变，不进行人脸识别、人物身份判断、
人物检索或身份数据库建设。

## 公开浏览器站点补充

静态公开站点继续采用 local-first 默认值。用户从本机选择的视频由当前
浏览器直接解码；匿名分析不把原视频、音频、帧、prompt 或报告发送到
VideoScope 服务端，也不要求注册。报告和压缩证据缩略图可以在用户
明确保存后写入当前浏览器的 IndexedDB，原视频 blob 和个人绝对路径
不得持久化。用户可以在隐私页面删除这些本地数据。

浏览器工作流与桌面 FFmpeg 工作流明确分离。浏览器只提供受控抽样的
四个 CPU 启发式检测器，不声称逐编码帧等价、统一质量分、真实准确率、
AI/OCR 推理或 Benchmark 能力。浏览器不支持某个编码时，用户应改用
桌面 CLI，而不是静默上传到远程转码服务。

以下行为属于用户明确选择的网络边界：

- 直接 URL 导入会在确认后联系用户输入的 HTTPS 主机；该主机可观察
  IP 和请求元数据，并且请求可能被 CORS 拒绝；
- 配置 Supabase 后，登录会向该服务发送认证所需数据；
- 只有独立启用分享、用户已登录并再次确认时，才发送经校验的脱敏
  报告投影；原视频和证据图片文件不在分享载荷中。

缺少 Supabase 配置时，站点使用 unavailable adapter，登录和分享显示
为不可用，但匿名本地分析保持完整。部署前必须另外验证回调白名单、
数据库迁移、两账户行级安全策略和撤销行为；代码中存在适配器不等于
生产认证或分享已经可用。
