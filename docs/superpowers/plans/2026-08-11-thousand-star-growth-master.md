# VideoScope Thousand-Star Growth Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved growth design into a truthful, zero-cloud-cost product funnel built around Video Rescue followed by Publish Ready.

**Architecture:** Four independently testable plans form one dependency chain: reproducible cases, public discovery pages, local outcome sharing, then community operations. The public site consumes static, versioned evidence; all video processing remains in the paired loopback connector, and external repository mutations remain separate approval gates.

**Tech Stack:** React 19, TypeScript 5.9, Vite 8, Python 3.11+, FastAPI, FFmpeg/ffprobe, Vitest, pytest, GitHub Actions, GitHub CLI.

## Global Constraints

- Preserve `local-first`, `CPU-first`, no default upload, no default model download, and no uncalibrated total quality score.
- The first 90-day public product is **Video Rescue + one-click Publish Ready**; A/D/B/C remain available but are not equal-weight homepage messages.
- Keep the source read-only and describe generated files as new, independently verified copies.
- Never claim “100% repaired”, universal restoration, real-video accuracy, or guaranteed platform acceptance.
- Fix the visible attribution to `Created by what912`; language switching must not alter the attribution.
- Case provenance is exactly `project-authored`, `user-authorized`, or `synthetic-regression`.
- `synthetic-regression` evidence must never be presented as a real user outcome.
- Do not add analytics SDKs, cookies, beacons, remote fonts, paid infrastructure, paid promotion, purchased Stars, Star swaps, or automated Stars.
- Show a Star invitation only after a `completed` outcome and an explicit playback or download action; never show it for `failed`, `cancelled`, `partial`, or `needs_review`.
- Treat 300–800 authentic Stars in the first 90 days and progress toward thousands over 6–12 months as directional goals, never as guaranteed results or advertised facts.
- Base validation remains offline and CPU-only; networked growth snapshots run only when explicitly invoked.
- Every implementation task must run its focused tests before the required repository validation `python scripts/validate.py`.
- No plan step authorizes `git push`, Pull Request creation, Discussions changes, repository settings changes, release creation, or deployment.

## Stop Conditions

Stop implementation and report the evidence instead of weakening a gate when any of these occurs:

- A demo output cannot be reproduced by the current public code.
- A before/after comparison uses different source time ranges.
- A generated artifact contains an absolute path, key, private prompt, source filename, or unapproved frame.
- A `needs_review`, `partial`, failed, or cancelled output is presented as success.
- Three or more zero-beginner testers block at the same onboarding step.
- Required Windows install/start/pair/process/uninstall smoke cannot be reproduced.
- A proposed channel requires paid hosting, paid API calls by the project owner, fake engagement, or mandatory signup before trying the product.
