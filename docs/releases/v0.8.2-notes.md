VideoScope v0.8.2 is a narrowly scoped Video Rescue reliability patch. It
packages the already merged full-output flow correction without changing the
reviewed processing thresholds, detector semantics, source-read-only contract,
or local-first CPU boundary.

## Fixed

- A reloaded Rescue job can serve its persisted damage map after the transient
  preparation object is no longer present, preventing a false “Damage map is
  not available” error during review.
- Stabilization generation still requires equal frame counts and exact
  timestamp inventories across the generated control and candidate siblings.
  The source parent retains its own timestamp digest instead of being required
  to share byte-identical normalized timestamps with re-encoded children.
- Confirmed processing can therefore reach the independently verified full
  faithful/improved output path. Bounded review previews remain intentionally
  short and are not presented as the final export.

## Compatibility and limits

- The Python distribution remains `genvideoscope`; the import and CLI remain
  `videoscope`.
- Python 3.11 and 3.12 remain supported.
- No AnalysisReport or Rescue schema migration is introduced.
- FFmpeg and ffprobe remain external prerequisites and are not bundled.
- Fixture and CI results are engineering evidence, not real-world recovery or
  artistic-quality claims.

## Install


from the [v0.8.2 GitHub Release](https://github.com/what912/VideoScope/releases/tag/v0.8.2).
