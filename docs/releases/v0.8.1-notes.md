# VideoScope v0.8.1 release notes

Status: **final release notes; publication pending**

Planned release: `0.8.1`

Reserved tag: `v0.8.1` (not created)

Previous immutable release: [`v0.8.0`](../release-checklist.md)

VideoScope v0.8.1 is a local-first stabilization and evidence release. It
packages the reviewed Video Rescue V15 qualification work, reproducible public
case studies and the full local four-mode demonstration while retaining the
existing source-read-only, preview, exact-confirmation and independent-
verification contracts.

## Highlights

- Adds bounded, measurement-gated Video Rescue qualification for tonal,
  deblur/sharpen clarity, audio denoise and transition stabilization. An output
  that does not satisfy the unchanged thresholds falls back instead of being
  presented as an improvement.
- Adds three reproducible, project-authored public cases and a deterministic
  local Check/A/D/B/C demonstration contract. Provenance, source/result
  boundaries, media identities and public allowlists are verified explicitly.
- Refocuses the public site on observable rescue outcomes, with dedicated
  download, examples, developer, community, roadmap and case-study routes.
- Pins release-sensitive native validation to FFmpeg/ffprobe 8.1.2.

## Reliability and security

- Normalizes bounded Windows retry behavior for transient atomic-publication
  failures in privacy, rescue, content and release-validation paths. Retry
  budgets remain finite, non-transient failures fail immediately, and existing
  destinations are never silently overwritten.
- Preserves prefix-durable validation evidence and fresh no-clobber audit roots
  so a failed gate remains inspectable.
- Updates the public-site lockfile to a secure transitive `nanoid` version while
  leaving `site/package.json` dependency declarations unchanged.
- Removes a Windows CI race from the Publish Ready SSE test by waiting for
  callback registration without weakening the production assertion.

## Compatibility

- The Python distribution remains `genvideoscope`; the Python import and CLI
  remain `videoscope`.
- Python 3.11 and 3.12 remain supported.
- The v0.1 `AnalysisReport` schema remains `0.1`; this release does not migrate
  or reinterpret existing Findings.
- Base installation remains CPU-first, offline-capable and model-free. FFmpeg
  and ffprobe remain external executables and are not bundled in the wheel.

## Verification record

The release workflow rebuilds and verifies every asset from the exact merged
`main` commit. Native validation uses fixed FFmpeg/ffprobe 8.1.2 and fresh
no-clobber logs, caches and temporary roots. The required record includes the
unified Python validation, dashboard and public-site checks, distribution
audit, exact-wheel offline smoke, Windows bundle audit, and installer
install/start/stop/uninstall smoke.

`release-evidence.json` binds the exact source commit to the primary wheel,
sdist and Windows installer hashes and sizes. `SHA256SUMS.txt` and the installer
sidecar provide the published checksums. These generated records, rather than
values copied into this document before the final build, are the authoritative
asset identities.

## Known limitations

- Video Rescue qualification is heuristic and fixture-bounded. It cannot
  reconstruct information absent from the source, and a technically passing
  output is not proof of artistic quality.
- Project-authored synthetic cases establish deterministic engineering
  behavior, not accuracy or usefulness on arbitrary user media.
- The release does not claim universal codec, player, browser, long-video or
  real-world benchmark coverage.
- The Windows installer is unsigned. Users should retain the documented
  unknown-publisher warning and verify its separately published SHA-256.
- FFmpeg and ffprobe remain external prerequisites and are not redistributed
  by the base package.

- `genvideoscope-0.8.1-py3-none-any.whl`

After PyPI publishes v0.8.1, install the exact Python release with:

```text
python -m pip install genvideoscope==0.8.1
```

Until publication is verified, README and Connector install surfaces continue
to reference the live v0.8.0 wheel. After publication, public download surfaces
must switch to verified official v0.8.1 asset URLs and matching checksums. The
immutable v0.8.0 release remains historical evidence and is not modified.
