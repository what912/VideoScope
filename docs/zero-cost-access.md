# VideoScope 零运营费访问与 BYOK 设计

状态：v0.8 实施基线

## 1. 目标与诚实边界

VideoScope 的公开入口保持为
`https://what912.github.io/VideoScope/`。项目方不托管用户视频、不运行
集中式分析队列、不保存用户 API Key，因此不承担持续的视频存储、
CPU/GPU 推理和第三方模型调用费用。

浏览器可以立即运行有限资源内的四个 CPU 检测器。需要 FFmpeg、完整
A/B/C/D 工作流、长视频、OCR/ASR 或高级 AI 时，公开站连接用户电脑上
一次安装、按需启动的 VideoScope Local Connector。计算、临时文件和
结果仍在用户电脑上。

纯静态网页无法在没有本机程序或云端服务器的前提下可靠运行 Python、
FFmpeg、处理任意长视频并安全保管第三方 API Key。因此“首次完全零安装、
无限长视频、全部桌面能力、真实云账号同步、项目方永远零费用”不能同时
成立。本设计优先保证完整能力、隐私和项目方零持续算力费；首次使用完整
能力需要安装本地连接器。

## 2. 三层产品

### 2.1 公开浏览器层

- 无需登录即可使用浏览器 CPU Quick Scan；
- 报告、偏好和本地身份只保存在浏览器设备；
- 检测到 Local Connector 后解锁完整模式；
- 不接收、存储或转发 API Key；
- 不加载分析、广告、遥测或远程运行时资源。

### 2.2 Local Connector

- 只绑定回环地址；
- Windows 官方安装器按当前用户安装，不需要管理员权限，不创建服务、不开放
  防火墙、不默认随系统启动；
- 可见启动窗口检查 FFmpeg/ffprobe、显示配对码，并只在服务确认启动后打开
  固定公开连接页；
- 复用同一套 Python/FFmpeg Pipeline，不复制分析逻辑；
- 为公开站提供精确来源白名单、配对码、短期会话和 CORS/PNA 响应；
- API Key 只在回环页面输入并保存在进程内存中，退出即清除；
- 对外响应、日志、报告和异常不得包含 API Key；
- 本地任务、产物和缓存继续采用现有保留与清理策略。

### 2.3 用户自带 AI（BYOK）

- 用户自行在模型供应商处开户、充值并创建 API Key；
- VideoScope 记录 provider、模型、能力、耗时和用量摘要，但不记录密钥；
- 调用前显示会发送的最小数据范围并要求明确确认；
- CPU 结果先完成，远程 AI 失败只形成隔离错误；
- 不把品牌名称等同于兼容性承诺，以协议和能力声明路由。

## 3. 登录与身份

默认身份是“本地设备账户”，不是伪装成云账号：

- 用户用显示名称和口令创建本地账户；
- 浏览器使用 PBKDF2 与 AES-GCM 加密账户资料；
- 口令、派生密钥和 API Key 不写入 localStorage、IndexedDB 或报告；
- 登录只解锁当前设备上的工作区；
- 提供加密备份导出与导入，供换浏览器或换电脑迁移；
- 清楚标注不提供服务器找回、跨设备自动同步或集中式账号管理。

可选 Supabase 适配器仍可用于部署者自行配置的云登录，但不是官方公开站
或完整功能的前置条件，也不能把 service-role key 暴露给静态客户端。

## 4. Connector 安全协议

1. Connector 启动时生成随机配对码并显示在本机窗口；源码开发方式才显示在
   当前终端，任何方式都不把配对码写入 URL、命令行参数、文件或访问日志；
2. 公开站先访问只读状态端点，再由用户输入配对码；
3. Connector 只接受配置中的精确 HTTPS 来源；
4. 配对码 10 分钟过期、成功后立即失效，连续错误尝试受限；配对成功返回有
   过期时间的随机会话令牌；
5. 非同源写操作要求 `X-VideoScope-Session`；
6. 预检只开放固定方法和请求头，并返回精确来源，不使用 `*`；
7. 会话、密钥保险库和确认记录只存在进程内存；
8. Connector 重启后必须重新配对和重新提供 API Key。

Windows 用户流程和故障处理见 `docs/windows-install.md`。

## 5. Provider 能力模型

Provider 不按营销品牌硬编码“全功能”。每个配置声明协议、能力、数据
去向、模型 ID、API 基址、请求超时和输出上限。v0.8 首先把
OpenAI-compatible 结构化文本能力接入已有高级内容工作流。

供应商的模型、价格、限额和兼容性会变化，预设只减少输入工作，不替代
供应商当前文档和用户验证。Gemini、Claude 等非兼容协议应由独立适配器
实现，不通过伪造 OpenAI-compatible 请求来冒充支持。

## 6. 验收标准

- 公开站在 Connector 离线时继续完成浏览器 CPU 分析；
- 精确来源之外的网页不能读取 Connector 响应；
- 未配对的公开站不能创建或控制本地任务；
- API Key 不出现在浏览器存储、进程日志、报告、错误或 OpenAPI Schema；
- OpenAI-compatible Provider 使用 Fake HTTP 端点完成离线单元测试；
- Provider 失败不删除 CPU 产物；
- 本地账户加密往返、错误口令、导入导出和删除均有测试；
- 中英文界面均明确区分浏览器模式、完整本地模式和远程 AI 数据传输；
- 基础验证不联网、不下载模型、不依赖 GPU。
