# VideoScope 产品规格

状态：v0.1 范围已冻结

文档版本：0.1

实现状态：v0.1 CPU 基础功能已实现，本文件继续定义验收边界

## 1. 产品定义

VideoScope 是一个 local-first 的生成视频质量诊断工具。用户提供一个
本地视频和可选的文本提示词，VideoScope 在本机完成分析，输出机器
可读的 JSON 报告和可离线查看的 HTML 报告。

核心流程固定为：

> 本地视频与可选提示词 → 确定性分析 → Findings → JSON / HTML 报告

每个 Finding 都必须回答：

- 问题发生在什么时间区间；
- 严重程度是什么；
- 该检测器给出的分数是什么；
- 支撑结论的证据是什么；
- 为什么产生这个结论。

VideoScope 是诊断工具，不是视频生成器、编辑器或自动评分裁判。

## 2. 目标用户

- 生成视频模型的研发和评测人员；
- 需要复查模型输出的质量工程师；
- 需要批量、可重复诊断视频的自动化测试维护者；
- 希望素材默认留在本地的创作者和研究人员；
- 需要把具体异常定位交给后续人工复核的开发团队。

## 3. 核心使用场景

### 3.1 单视频诊断

用户通过 CLI 输入本地视频，获得按时间排序的异常清单、证据帧和
离线报告，快速跳转到需要复查的片段。

### 3.2 生成流水线回归检查

自动化任务对固定样例运行 VideoScope，读取 JSON 中的 Findings 和
检测器状态，发现新增的黑屏、冻结、模糊或闪烁异常。

### 3.3 Benchmark

维护者对带有预期区间标注的公开或本地测试集运行固定配置，验证
检测器行为、性能和回归。v0.1 不声明未经测量的准确率。

### 3.4 人工复核交接

质量工程师打开离线 HTML，通过时间轴、严重程度、问题区间、解释
和证据帧判断是否需要进一步调查。

## 4. 输入

### 4.1 必需输入

- 一个可由本机 FFmpeg/ffprobe 读取的本地视频文件。

### 4.2 可选输入

- 文本提示词。v0.1 接受该输入，但不进行提示词—视频语义匹配，也
  不影响任何 v0.1 检测器结果。
- 显式配置文件或 CLI 参数，用于覆盖已记录的检测阈值和输出位置。

### 4.3 输入约束

- 默认不接受远程 URL；
- 不修改源视频；
- 不把绝对个人路径写入报告；
- 默认不把原始提示词写入报告，只记录是否提供及可选的内容摘要；
- 无法探测或解码的视频必须产生明确的运行错误报告，不得伪造
  Findings。

## 5. 输出

一次分析生成一个本地输出目录，至少包含：

- `report.json`：符合 `docs/report-schema.md` 的机器可读报告；
- `report.html`：无需网络请求即可查看的 HTML 报告；
- `evidence/`：报告引用的证据帧或帧对，使用相对路径。

HTML 报告必须展示：

- 视频元数据摘要；
- 检测器运行状态；
- 按时间排列的时间轴；
- Finding 严重程度和类型；
- 精确问题区间；
- 分数及其检测器内含义；
- 解释和证据帧；
- `detector_error`，使用户知道哪些检查没有完成。

报告不得包含一个没有校准依据的“总质量分”。

## 6. v0.1 功能范围

### 6.1 视频格式和元数据检查

通过 ffprobe 读取容器、视频流、时长、尺寸、帧率、像素格式等可用
信息，并报告缺失、矛盾或无法支持后续分析的情况。

### 6.2 镜头边界检测

生成有序且不重叠的镜头区间，供后续检测器进行场景内归一化，并
为闪烁检测排除镜头切换邻域。

### 6.3 黑屏或近黑屏区间检测

检测持续达到配置阈值的黑屏或近黑屏片段，合并相邻帧为时间区间，
输出代表性证据帧。

### 6.4 冻结、卡帧或连续近重复帧检测

检测持续的完全重复或近重复帧序列，避免把单个静态画面直接等同于
故障，并输出区间和帧对证据。

### 6.5 场景内相对模糊异常检测

在同一镜头内部建立相对基线，检测显著偏离该镜头常态的模糊区间。
该检测器不把低景深、运动模糊或整体柔焦自动宣称为绝对质量错误。

### 6.6 排除镜头切换后的全局亮度闪烁检测

检测全局亮度的异常短期波动。镜头切换及其配置化保护窗口内的变化
不得作为闪烁 Finding。

### 6.7 报告、CLI、Benchmark 和测试

- 提供稳定、可脚本调用的 CLI；
- 输出 JSON 和离线 HTML；
- 提供覆盖成功、部分失败和全局失败路径的自动化测试；
- 提供可重复运行的 Benchmark，固定配置、数据清单和结果格式；
- 不用未经测量的数据声明检测准确率。

## 7. v0.1 明确非目标

v0.1 不包含：

1. 视频生成；
2. 视频修复或自动编辑；
3. 人脸身份识别；
4. 对真实人物进行身份判断；
5. 准确判断复杂物理规律是否违反；
6. 用未经校准的权重合成总质量分；
7. 默认上传视频、帧、提示词或报告到外部服务；
8. 默认下载大型模型；
9. 提示词与视频内容匹配度；
10. 本地 Web 服务或云端控制台。

任何未来插件都不能让这些能力变成 v0.1 的隐式依赖。

## 8. 隐私原则

- local-first：核心 v0.1 流水线必须可在离线 CPU 环境运行；
- 默认零上传、零遥测、零外部 API 调用；
- 源视频只读；
- 报告不记录绝对个人目录、环境用户名或未脱敏异常堆栈；
- 原始提示词默认不写入报告；
- 证据只截取诊断所需帧，并由用户控制输出目录；
- 远程或 AI 插件必须由用户显式安装、配置和启用，并清楚说明数据
  去向；它们不属于 CPU 基础版。

## 9. CPU 基础版与可选 AI 版

### CPU 基础版

- 包含全部 v0.1 验收能力；
- 只依赖本地传统视频处理和确定性数值算法；
- 不需要 GPU、外部服务或大型模型；
- 默认安装和默认 CLI 路径只启用 CPU 检测器。

### 可选 AI 版

- 是未来的插件集合，不是独立替换基础版的产品；
- 可用于提示词匹配、语义漂移、文字稳定性或 VLM 解释；
- 必须显式启用，并在报告中记录插件、模型和配置版本；
- 失败不得影响 CPU 基础 Findings；
- 远程 AI 插件必须在执行前明确提示数据传输范围。

## 10. Finding 规范

每个 Finding 必须至少包含：

- 稳定标识 `id`；
- 检测器标识和 Finding 类型；
- `start_seconds`、`end_seconds` 浮点秒时间区间；
- 枚举化严重程度 `severity`；
- `[0, 1]` 范围的检测器内分数 `score`；
- 非空证据列表 `evidence`；
- 面向用户的解释 `explanation`。

分数只表达该检测器内、该版本和该配置下的异常强度或置信程度，不
允许跨检测器相加、平均或排序成一个总质量分。视觉异常至少有一个
证据帧或帧对；纯元数据异常可使用结构化元数据证据。

## 11. 确定性和故障隔离

给定相同的输入字节、文件名、工具版本、插件版本和完整配置：

- Findings、镜头区间、证据选择、ID 和排序必须一致；
- JSON 使用稳定字段和数组顺序；
- HTML 展示顺序必须一致；
- Findings 的内容、ID、证据和排序不得包含随机值；`analysis_id` 与
  `created_at` 是允许变化的运行信封字段，比较确定性结果时应忽略。

每个检测器独立运行和记录状态。单个检测器异常时：

- 编排器捕获异常；
- 该检测器状态记录为 `detector_error`；
- 报告整体状态记录为 `partial`；
- 已成功检测器的 Findings 和证据仍然输出；
- 默认错误信息必须可操作且脱敏。

只有输入无法读取、核心媒体探测失败或报告无法写入等全局错误，才
允许报告整体为 `failed`。

## 12. v0.1 验收标准

v0.1 可发布必须同时满足：

1. 在支持的 CPU 环境，对有效本地视频执行一条 CLI 命令即可生成
   `report.json`、`report.html` 和所需证据；
2. 六类基础分析能力均可运行：元数据、镜头、黑屏、冻结、相对模糊、
   排除切镜的全局亮度闪烁；
3. 每个 Finding 通过报告模式校验，并包含时间区间、严重程度、分数、
   证据和解释；
4. HTML 在断网环境中完整显示时间轴、区间、严重程度和证据帧；
5. 闪烁测试证明切镜保护窗口中的亮度跳变不会生成闪烁 Finding；
6. 同一输入和配置重复运行得到确定性 Findings、证据选择与序列化
   顺序；
7. 注入单个检测器失败时，仍产生 `partial` 报告并记录
   `detector_error`；
8. 无法解码的输入产生明确的失败结果和非零 CLI 退出码；
9. 自动化测试覆盖各检测器的正例、负例、边界条件和报告契约；
10. Benchmark 可在固定清单和配置上无人值守运行，并输出机器可读
    结果；
11. 默认执行期间不产生网络请求，也不下载模型；
12. 文档和 CLI 不宣称未经 Benchmark 验证的准确率。

## 13. 产品范围变更规则

v0.1 范围内可以调整阈值、性能和实现，但不得引入本文件的非目标。
新增语义或 AI 能力必须作为可选插件进入未来版本，并同步更新产品
规格、报告模式和路线图。
